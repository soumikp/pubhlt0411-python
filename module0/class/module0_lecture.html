A notebook preserves execution state, not screen order

Notebooks contain code cells and text cells. Shift+Enter executes a cell and advances.

The consequential property: the interpreter retains what was executed, not what is displayed.

population = 143786      # executed first

population = 157795      # executed second

# The first cell is then edited to 999999 and NOT re-executed.
# The value of population remains 157795.

Execution order is invocation order

Execution does not proceed top to bottom. The bracketed number beside each cell records the true sequence. This accounts for roughly half of all inexplicable notebook behavior.

Resolution: Kernel > Restart Kernel and Run All Cells, which is also the test of whether a notebook is reproducible.

Values.

“The time has come,” the Walrus said, “to talk of many things”.

– Lewis Carroll, Through the Looking-Glass.

Assignment binds a name to a value

The = operator does not assert equality. It binds: the expression on the right is evaluated, and the name on the left refers to the result.

The statement is read right to left: construct the value, then attach the name.

R analogue

county <- "Schuylkill". The semantics are equivalent. Python uses = and provides no <-.

Identifier choice is a documentation decision

Constraints: letters, digits, underscores; no spaces; no leading digit. Identifiers are case-sensitive — Population and population denote different names.

Convention: lower_case_with_underscores, not PopulationCount.

Readability is an assessed criterion

Identifier quality falls under presentation, which is a named grading criterion in this course.

Every value carries a type that determines valid operations

Four types account for nearly all data handled in this course.

type() reports the type of any value and is the appropriate diagnostic when an operation behaves unexpectedly.

R analogue

character, integer, numeric, logical. Python writes True and False, not TRUE and FALSE.

Python does not coerce between text and numbers

Scenario: a file supplies "60" as text. Adding eight should yield 68.

TypeError — unsupported operand types

TypeError: can only concatenate str (not "int") to str

The + operator is defined for str + str (concatenation) and for int + int (addition), but not across the two. Rather than infer an intent, the interpreter raises.

Resolution: convert explicitly — int(overdose_deaths) + 8.

Conversion between types is explicit

int() truncates toward zero

int(41.7) evaluates to 41. The fractional component is discarded rather than rounded. round(41.7) performs rounding and evaluates to 42.

Seven arithmetic operators

Three operators warrant particular attention

/ returns a float even when the division is exact. // discards the remainder. Exponentiation is **; the ^ operator denotes bitwise exclusive-or and evaluates without error to an incorrect result when used for powers.

Exercise: compute a rate per 100,000

A rate per 100,000 is the count divided by the population, multiplied by 100,000. Schuylkill County, 2023.

# The multiplier is 100000, written without a comma separator.
# Python parses 100,000 as two values, not one, and the result will not be a rate.
overdose_deaths = 60 population = 143786 rate_per_100k = overdose_deaths / population * 100000 print(rate_per_100k) 
overdose_deaths = 60
population = 143786

rate_per_100k = overdose_deaths / population * 100000

print(rate_per_100k)

The output carries excessive precision

41.728680121847745 is arithmetically correct and unsuitable for presentation. Formatting is addressed on the following slide.

f-strings interpolate values into text

An f prefix on a string literal causes each {expression} to be evaluated and substituted.

The :.1f format specifier fixes the output at one digit after the decimal point; :.2f gives two.

Format at presentation, retain full precision in computation

Rounding applied at the point of printing does not affect stored values. Rounding applied during computation propagates through every subsequent step.

Comments document rationale, not syntax

Text following # is ignored by the interpreter and addressed to the reader.

Comments are assessed

Interpretation and presentation together account for the majority of the grading criteria. Comments are where analytic reasoning becomes visible to a reader.

Final exercise: how often?

In 2023, how often did an overdose death occur in each county? Report days and hours.

# `//` keeps the whole days; `%` keeps the hours left over.
# 365 / 60 gives 6.083 days, which is not how anyone describes time.
hours = 365 * 24 # hours between deaths schuylkill_gap = hours // 60 s_days = schuylkill_gap // 24 s_hours = schuylkill_gap % 24 centre_gap = hours // 7 c_days = centre_gap // 24 c_hours = centre_gap % 24 print(f"Schuylkill: {s_days} d {s_hours} h") print(f"Centre: {c_days} d {c_hours} h") 
hours = 365 * 24

# hours between deaths
schuylkill_gap = hours // 60
s_days = schuylkill_gap // 24
s_hours = schuylkill_gap % 24

centre_gap = hours // 7
c_days = centre_gap // 24
c_hours = centre_gap % 24

print(f"Schuylkill: {s_days} d {s_hours} h")
print(f"Centre:     {c_days} d {c_hours} h")
